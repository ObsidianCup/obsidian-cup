# UX Profile

Written 14 Nov 2026 from decisions the owner had already made (see
`docs/HANDOVER.md`, "Site basics"). All UI/UX skills in this project read this
file before changing layout, copy, or interaction. The owner can change any line.

## Aesthetic reference

- **Standard:** Custom ("Obsidian Glass", refreshed 9 Nov 2026)
- **Notes:** Dark, calm, typographic. Page #0b1012, panels #151c1f, lines
  #2a3337 / #3d484c, text #eeeae3, soft #c9cfd0, mist #a7b0b2. Ice #d7e9ec is
  the one main-action and focus colour. Amber #f2b84b only for "Next up" and
  live status. Unbounded 500/600 for headings, Figtree 400/500 for text, Noto
  Sans Bengali for Bangla; at most three weights, none over 600. Body 16px,
  secondary 14px, nothing under 12px. 8px grid. Story text on laptops:
  heading left, text right, about 75 characters a line. "Glass" is the name
  of the stone, not the effect: no blur, no translucent panels.

## Banned anti-aesthetics

- Glassmorphism / `backdrop-filter`
- Floating pastel pill badges for ordinary metadata
- Decorative gradients and glowing borders
- Rainbow gradients on buttons
- Cartoon empty-state illustrations
- Nested scrollbars and icon bloat inside inputs
- All-caps text; title case (sentence case everywhere)
- Scroll effects that change layout, hijack scrolling, or loop (sections
  arriving once as they scroll into view are allowed in showy mode, see Motion)
- Identical boxed cards for content that is not a set of choices
- AI-generated photos of players; traced or copied artwork
- Placeholder content on the live site

## Accessibility target

- **Level:** WCAG 2.1 AA
- **Contrast:** 4.5:1 for text, 3:1 for large text and control borders
- **Touch / focus:** 44px tap areas; visible Ice focus ring; buttons are never
  disabled (busy state through `ocBusy` / `ocIsBusy`); every icon-only button
  has a tooltip

## Brand tone and microcopy voice

- **Voice:** Warm & Humancentric
- **Capitalization:** Sentence case for UI copy and buttons
- **Notes:** Plain words for players and parents, many reading in a second
  language. Never "football" (the sport is futsal). No "the leading". Errors
  say what happened and what to do next, never blame. The owner writes
  Bangla; new English strings get an empty Bangla entry.

## Icon library

- **Library:** Project SVG
- **Package / path:** inline SVG in `js/components.js` and page markup
- **Notes:** No icon package. No emoji as icons.

## Motion

Two modes for the public pages, chosen in `js/motion-boot.js`
(`MOTION_DEFAULT`, **showy since 16 Nov 2026**); preview the other with `?motion=showy` / `?motion=calm`.

- **Calm:** short transitions tied to an action plus a 200ms page fade.
  Durations 100 / 150 / 200 / 300ms only.
- **Showy** (owner asked for it on 16 Nov 2026, lifting her earlier ban on
  scroll effects): one opening per page (home: headline, then a ball that
  flies in and lands as the "Next up" dot; inner pages: heading and a line
  that draws), sections and list items arriving once as they scroll into
  view, a faint background of stone facets that shifts with scroll and
  pointer, a progress line, page-to-page transitions. Owner-approved
  exceptions to the timing scale, public pages only: 600ms for an arriving
  section and for the ball, 60ms between list items (at most 7 steps).
- Both modes: movement through `transform`, `opacity` and `clip-path` only;
  no layout animation; no looping decoration (loops only for real live
  status); everything off under reduced motion; nothing may stay hidden if a
  script fails. Account, organiser and legal pages always stay calm.

## Agent rules

1. Read this profile before creating or editing any UI, CSS, or microcopy.
2. Prefer skills by task: new page → `page-patterns` (name the pattern before markup); layout / chrome → `viewports`; forms → `forms`; overlays → `surfaces`; loaders → `loaders`; empty views → `empty-states`; motion → `motion`. Before finishing UI, run `ux-audit`.
3. Use only project SVG icons. Do not mix icon sets or use emoji as UI icons.
4. Never introduce items on the banned list.
5. Destructive actions always use an explicit confirmation dialog that names the thing.
